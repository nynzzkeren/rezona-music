## PART 1: COVER-TO-BACKGROUND BLEND (Now Playing)
PROBLEM (see rezona_now.jpg): the cover ends at a hard horizontal edge and below it is a near-black purple block unrelated to the cover; controls look like dark boxes. TARGET (player_blend.jpg): the cover is full-bleed from the very top (under the status bar) and its lower part dissolves smoothly into a solid background that has the SAME color family as the cover (e.g. warm brown for an orange cover). Everything below sits on that one continuous colored background.
Implement:
1. Palette: extract from the cover (Palette/Coil) the dominant swatch and the average color of the cover's bottom strip. Compute ambientBase from them: keep the hue and most of the saturation (no forced purple or black), lightness clamped to about 0.10-0.20 so white text stays readable. For near-gray/black/white covers use a neutral deep tone with a slight tint. Precompute asynchronously before the track change to avoid flashes.
2. Layout: the cover fills the full width, starts at y=0, height about 1.25x the screen width (center-crop). Fade the cover's lower ~40% into ambientBase using an alpha mask (offscreen layer with vertical gradient, DstIn) so there is NO visible edge; the color under the fade is exactly ambientBase. Add very subtle noise or dither to avoid banding. Below the fade, the background is ambientBase with soft radial glows of the cover colors; it is the same continuous ambient layer used app-wide.
3. Controls zone on the ambient background: title and artist left aligned; heart and three-dot as 48dp glass circles tinted with the cover hue (tint = ambientBase lightened 12-18% at 35-50% alpha, white specular rim); progress line, times, transport (bare icons, glass bubble only while pressed), volume slider. The bottom pill (Part 2) uses the same tinted glass. No black or purple boxes anywhere.
4. Header overlay at the top-left: "Now playing" and the queue name in bold italic (tap opens the Queue sheet).
5. Crossfade cover + ambient colors 700ms on track change. Mini player and dock use the same tint logic.
6. Contrast guard: if text over the fade region drops below 4.5:1, add a minimal scrim only there.
7. Test with 8 real covers: orange/brown, red, blue, green, pure black, white, pastel, black-and-white. Report any that look wrong and fix them.

## PART 4: BUTTER-SMOOTH LYRICS (lyrics_motion.mp4)
PROBLEM: lyric scrolling and the line fill feel stuttery ("cedet-cedet"). Target: the smoothness in lyrics_motion.mp4, including when seeking. First profile with JankStats/Perfetto and report the real causes, then fix them with this architecture:
1. Playback clock: create a frame-synced PlaybackClock for lyrics. ExoPlayer's position updates only every few hundred ms, so interpolate between polls using elapsedRealtime delta x playbackSpeed on every frame (Choreographer/withFrameNanos) and re-sync gently when drift exceeds ~120ms. On seek, snap the clock immediately.
2. Continuous focus value: compute focusIndex as a Float (active line index + eased progress through the line). All visuals (scroll, alpha, scale, blur, fill) derive from this continuous value so nothing steps or jumps.
3. Scroll: one Animatable scroll offset with a spring (dampingRatio ~0.9, low stiffness, no overshoot) toward the active line's center, using measured line tops in the content's own coordinate space. Never call scrollToItem per frame. Large seeks use a short critically-damped glide. Manual scroll pauses auto-follow for 3 seconds then glides back; tapping a line seeks.
4. Per-line rendering in graphicsLayer lambdas (no recomposition): alpha, scale (1.0 down to ~0.94), and blur radius from the distance to focusIndex. Blur only on API 31+ and only for lines within 4 positions of the active line, quantized to 1dp steps with reused RenderEffects; lines beyond ~6 away are not drawn. If jank is detected at runtime, automatically drop blur and keep alpha/scale.
5. Word-by-word fill: cache text layouts once (TextMeasurer/TextLayoutResult), draw the dim text plus the bright text clipped by a soft-edged gradient mask whose position follows word progress, in the draw phase only. If no word timestamps exist, use a smooth line-level fade.
6. No allocations per frame, immutable stable lyric models, stable keys, read animated values only inside graphicsLayer/draw lambdas, no per-line animate*AsState in a loop, translation lines laid out with their original line as one item.
7. Budget: 60fps (120Hz where supported), zero frames over 16ms across 60 seconds of playback with seeking, measured on my phone. Report janky-frame percentage before and after.
8. Edge cases: seeking, pause/resume, track change, rotation, 2-3 row wraps, first/last lines, instrumental gap dots, long lines.
Delete any leftover highlight-box code from the lyrics screen.
